## **1\. Загальна інформація про проєкт** {#1.-загальна-інформація-про-проєкт}

### **1.1. Назва та мета** {#1.1.-назва-та-мета}

**FinanceBot** — особистий Telegram-бот для швидкого обліку витрат. Користувач надсилає одне повідомлення («150 продукти», «таксі 500»), бот розпізнає суму й категорію та записує витрату в Google-таблицю.

Головна цінність — швидкість: запис витрати займає одне повідомлення або 2–3 натискання кнопок. Google-таблиця слугує сховищем даних і місцем для перегляду та ручного редагування на комп'ютері.

### **1.2. Цільова аудиторія** {#1.2.-цільова-аудиторія}

* Перша версія: один користувач, власниця бота (Антоніна).  
* Згодом: члени родини та, можливо, покупці копій бота (див. 1.3).

### **1.3. Модель використання** {#1.3.-модель-використання}

**Одна копія бота \= один користувач \= одна Google-таблиця.**

* Кожна людина має власного бота (створеного через @BotFather), власну таблицю й власні налаштування. Копії між собою не пов'язані.  
* Кілька копій можуть працювати на одному сервері: той самий код запускається з різними файлами налаштувань.  
* Можлива модель розповсюдження в майбутньому: продаж копії («коробка») — код, шаблон таблиці й інструкція з налаштування.

### **1.4. Стек технологій** {#1.4.-стек-технологій}

| Компонент | Рішення |
| ----- | ----- |
| Мова | Python 3 |
| Бібліотека Telegram | aiogram 3.x |
| Налаштування й секрети | файл `.env` через python-dotenv; шаблон `.env.example` без реальних значень |
| Сховище даних | Google Sheets через Google Sheets API (сервісний акаунт Google), бібліотека gspread або аналог — на розсуд розробника |
| Нечіткий пошук | бібліотека rapidfuzz або аналог — на розсуд розробника |
| Структура коду | основний файл `app/main.py`, залежності в `requirements.txt` |
| Контроль версій | git, окремий репозиторій `financebot` на GitHub (акаунт Ann-sw), робота через гілки та pull request |
| Хостинг | етапи 1–2: Mac власниці (режим polling); постійний хостинг — див. 8.3 |

Розробка ведеться методом vibecoding за допомогою Claude Code.

## **2\. Терміни та глосарій** {#2.-терміни-та-глосарій}

| Термін | Значення |
| ----- | ----- |
| Власник | єдиний користувач копії бота; визначається за Telegram ID у налаштуваннях |
| Витрата (запис) | один рядок у вкладці «Витрати» з унікальним ID |
| Опис | текст з повідомлення без суми й слова дати («білет автобус Варшава»); за ним бот визначає категорію й навчається |
| Коментар | уточнення до запису, додане кнопкою «Додати коментар»; на навчання не впливає |
| Словник | вкладка таблиці з парами «ключове слово → категорія» |
| Активне слово | слово словника, яке бот використовує для розпізнавання |
| Кандидат | слово, для якого категорію обрали вручну лише один раз; для розпізнавання не використовується |
| Самонавчання | автоматичне поповнення словника з ручних виборів і виправлень категорії |
| Нормалізація | підготовка тексту до пошуку: нижній регістр, зведення польських літер (ż→z, ą→a), пошук за початком слова |
| Нечіткий пошук (fuzzy) | розпізнавання слів із одруківками за відсотком схожості («rossman» ≈ «rossmann») |
| Сумнівне розпізнавання | слово схоже на словникове, але не збігається точно; бот перепитує |
| Незавершена дія | стан, коли бот чекає відповіді (категорію, суму, коментар, нове значення) |
| Inline-кнопки | кнопки під конкретним повідомленням бота |
| Кнопка «Меню» | стандартна кнопка Telegram ліворуч від поля введення, що відкриває список команд |
| Команда | службове повідомлення з «/» (`/add`); у Telegram назви команд лише латиницею |
| Сервісний акаунт Google | технічний акаунт, від імені якого бот читає й пише таблицю; таблицю треба відкрити для його адреси з правом «Редактор» |
| Токен бота | «пароль» бота від @BotFather; зберігається лише в `.env` |

## **3\. Функціональні вимоги** {#3.-функціональні-вимоги}

Перша версія враховує лише витрати в злотих (zl). Доходи, валюти, аналітика й ШІ — у розділі 9\.

### **3.1. Доступ** {#3.1.-доступ}

1. Користувач починає роботу командою `/start`; бот відповідає коротким привітанням і прикладом введення («Напишіть, наприклад: 150 продукти»).  
2. Реєстрації й паролів немає. Бот обробляє повідомлення лише від Telegram ID власника, вказаного в `.env`.  
3. Повідомлення від будь-кого іншого бот ігнорує (нічого не відповідає й нічого не записує).

### **3.2. Текстове введення витрати** {#3.2.-текстове-введення-витрати}

1. Одне повідомлення \= одна витрата.  
2. **Сума** — число в будь-якому місці повідомлення: «150 продукти» і «продукти 150» дають однаковий результат.  
   * Дробова частина через крапку або кому (12,27 або 57.45), не більше 2 знаків.  
   * У таблицю сума записується як число (не текст) і відображається з комою: 12,27.  
   * Сума має бути більшою за 0\.  
   * Якщо в повідомленні кілька чисел («2 булочки 8»): бот питає «Яка сума?» і показує кнопки \[2\] \[8\] \[❌ Скасувати\].  
3. **Опис** — увесь текст без суми й слова дати. Зберігається повністю, як написано: «білет автобус Варшава» не скорочується до «проїзд».  
4. **Дата**:  
   * без слова дати — сьогодні;  
   * «сьогодні», «dziś», «сегодня», «today» — сьогодні;  
   * «вчора», «wczoraj», «вчера», «yesterday» — вчора;  
   * «позавчора», «przedwczoraj», «позавчера» — позавчора;  
   * будь-яку іншу дату задають після запису через \[✏️ Змінити\] → \[Дата\] (див. 3.8).  
5. **Тільки число** («150»): бот одразу показує кнопки категорій, опис залишається порожнім.  
6. **Немає числа** («продукти»): бот питає «Яка сума?» з кнопкою \[❌ Скасувати\], чекає число і далі працює як звичайно.  
7. Витрати можна писати українською, польською, російською та англійською. Бот не перекладає: словник містить слова всіма цими мовами.

### **3.3. Введення через меню (спочатку категорія)** {#3.3.-введення-через-меню-(спочатку-категорія)}

1. Команда `/add` (кнопка «Меню») → бот показує список категорій і кнопку \[❌ Скасувати\].  
2. Після вибору категорії бот редагує те саме повідомлення: «Здоровʼя → введіть суму (можна з описом)» з кнопками \[⬅️ Назад\] \[❌ Скасувати\]. «Назад» повертає до списку категорій.  
3. Користувач надсилає суму («45» або «45 вітамін Д»). Категорія вже відома, тому розпізнавання не запускається; слова опису проходять самонавчання як ручний вибір (3.7).

### **3.4. Категорії** {#3.4.-категорії}

їжа · побут · бізнес-банк · підписки · проїзд · квартира · телефон-інтернет · репетитор · здоровʼя · одяг · для себе.

Службова 12-та категорія **«нерозпізнане»**: у неї потрапляє витрата, для якої категорію так і не обрали (нова витрата або тайм-аут, див. 3.12). Вона не показується серед кнопок вибору. Список категорій зберігається у вкладці «Налаштування», а не в коді.

### **3.5. Розпізнавання категорії** {#3.5.-розпізнавання-категорії}

Категорія визначається за описом тільки серед **активних** слів словника. ШІ в першій версії не використовується.

1. **Нормалізація**: нижній регістр; польські літери зводяться до латиниці («zabka» \= «żabka»); апострофи ʼ, ' та ’ вважаються однаковими.  
2. **Точний збіг або збіг за початком слова**: «продуктів» знаходиться через «продукт». Результат — запис без запитань («Як визначено» \= словник).  
3. **Нечіткий пошук** (одруківки):  
   * схожість від 85% — запис без запитань («Як визначено» \= нечітко);  
   * від 70% до 85% — сумнівне розпізнавання: «200 — «Rossman» → **побут**?» з кнопками \[✅ Так\] \[Інша категорія\] \[❌ Скасувати\];  
   * пороги 85% і 70% — стартові, уточнюються під час тестування і задаються в налаштуваннях.  
4. **Слова з опису вказують на різні категорії** («аптека rossmann»): бот вважає це сумнівним і показує кнопки знайдених категорій \+ \[Інша категорія\] \[❌ Скасувати\].  
5. **Нічого не знайдено**: бот зберігає суму й опис у тимчасовому стані та відповідає:

> 💰 200 — «Decathlon» Не впізнав категорію. Оберіть: \[їжа\] \[побут\] \[бізнес-банк\] \[підписки\] \[проїзд\] \[квартира\] \[телефон-інтернет\] \[репетитор\] \[здоровʼя\] \[одяг\] \[для себе\] \[❌ Скасувати\]

Після вибору витрата записується («Як визначено» \= вручну). «Скасувати» — нічого не записується, бот пише «Скасовано».

### **3.6. Підтвердження запису** {#3.6.-підтвердження-запису}

Після успішного запису в таблицю:

> ✅ Додано: 200 · одяг · Decathlon 🧠 Тепер «Decathlon» → одяг \[✏️ Змінити\] \[📝 Додати коментар\] \[🗑 Видалити\]

1. Якщо дата не сьогоднішня, вона додається до рядка: «✅ Додано: 300 · квартира · чинш · 26.10».  
2. Рядок 🧠 з'являється лише тоді, коли змінився словник (слово стало активним або змінило категорію).  
3. Кнопки дій показуються лише під останнім записом. Коли з'являється новий запис, бот прибирає кнопки з попереднього підтвердження (текст лишається). Для старіших записів — команда `/last` (3.11).  
4. Всі кнопки посилаються на **ID запису**, а не на номер рядка. Якщо запису з таким ID уже немає, бот відповідає «Запис уже видалено або змінено в таблиці» і нічого не робить.

### **3.7. Самонавчання словника** {#3.7.-самонавчання-словника}

1. Словник поповнюється з кожного **ручного** вибору категорії: кнопки після «Не впізнав», «Інша категорія», вибір через `/add`, виправлення через \[✏️ Змінити\] → \[Категорія\].  
2. Якщо опис довгий («білет автобус Варшава»), вчиться кожне слово опису від 3 літер, якого ще немає в словнику: воно стає кандидатом. Випадкові слова не стануть активними, бо рідко повторюються з тією самою категорією.  
3. **Кандидат**: перший ручний вибір додає слово зі статусом «кандидат» і лічильником 1\. Для розпізнавання воно не використовується.  
4. **Активація**: другий ручний вибір тієї самої категорії для цього слова робить його «активним»; бот пише «🧠 Тепер «Decathlon» → одяг».  
5. Якщо для кандидата обрали іншу категорію, його категорія замінюється на нову, лічильник скидається до 1\.  
6. **Автоочищення**: кандидати, що за 3 місяці з «Останнього використання» не отримали другого підтвердження, видаляються. Перевірка — раз на добу або при запуску бота. Активні слова не видаляються.  
7. **Конфлікт**: якщо активне слово має категорію А, а вручну обрали Б, бот не перезаписує мовчки, а питає: «Rossmann зараз → побут. Змінити на здоровʼя назавжди чи лише цього разу? \[Назавжди\] \[Лише цей раз\]». Витрата в будь-якому разі записується в категорію Б.  
8. Колонки словника оновлюються автоматично: «Підтверджень» \+1 при кожному записі за цим словом, «Останнє використання» — дата останнього запису.  
9. Обмеження за розміром словника немає.

### **3.8. Редагування запису \[✏️ Змінити\]** {#3.8.-редагування-запису-[✏️-змінити]}

1. Бот питає «Що змінити?» і показує \[Сума\] \[Категорія\] \[Опис\] \[Дата\] \[❌ Скасувати\].  
2. **Сума**: «Введіть нову суму» → перевірка за правилами 3.2.  
3. **Категорія**: список категорій з \[⬅️ Назад\]; вибір вважається ручним і проходить самонавчання та перевірку конфлікту (3.7).  
4. **Опис**: «Введіть новий опис». Категорія автоматично не перераховується.  
5. **Дата**: кнопки \[Сьогодні\] \[Вчора\] \[Позавчора\] або дата текстом у форматі `ДД.ММ` чи `ДД.ММ.РРРР`. Майбутні дати не приймаються.  
6. Після зміни бот оновлює рядок у таблиці (включно з колонкою «Змінено») і редагує повідомлення-підтвердження, наприклад «✅ Оновлено: 45 · здоровʼя · аптека».

### **3.9. Коментар \[📝 Додати коментар\]** {#3.9.-коментар-[📝-додати-коментар]}

1. Бот пише «Напишіть коментар» з \[❌ Скасувати\] і чекає текст.  
2. Коментар записується в колонку «Коментар»; повторне додавання замінює старий коментар.  
3. Підтвердження оновлюється: «✅ 45 · здоровʼя · аптека» \+ «💬 вітамін Д».  
4. Коментар не впливає на словник. Відповідь Reply на повідомлення як спосіб додати коментар не підтримується.

### **3.10. Видалення \[🗑 Видалити\]** {#3.10.-видалення-[🗑-видалити]}

1. Рядок видаляється з таблиці повністю, без додаткового перепитування.  
2. Бот редагує підтвердження на «🗑 Видалено: 45 · здоровʼя · аптека» з кнопкою \[↩️ Відновити\].  
3. «Відновити» працює, доки не внесено наступну витрату: рядок повертається з тим самим ID і даними. Для цього бот тимчасово зберігає дані видаленого запису.  
4. Видалення витрати не змінює словник.

### **3.11. Останні записи `/last`** {#3.11.-останні-записи-/last}

1. Бот показує 5 останніх внесених записів одним повідомленням (номер · дата · сума · категорія · опис) і кнопки \[1\] \[2\] \[3\] \[4\] \[5\] \[✖️ Закрити\].  
2. Натискання номера відкриває цей запис з кнопками \[✏️ Змінити\] \[📝 Додати коментар\] \[🗑 Видалити\] \[⬅️ Назад\]; текст і кнопки замінюються в тому ж повідомленні.

### **3.12. Незавершені дії та скасування** {#3.12.-незавершені-дії-та-скасування}

| Бот чекає | Надійшла нова витрата | Минуло 30 хв без відповіді | `/cancel` або \[❌ Скасувати\] |
| ----- | ----- | ----- | ----- |
| вибір категорії або «Так / Інша» | попередня витрата записується як «нерозпізнане», нова обробляється | записується як «нерозпізнане» | нічого не записується |
| суму («Яка сума?») | число вважається відповіддю | скасовується, нічого не записується | нічого не записується |
| коментар або нове значення для «Змінити» | текст вважається відповіддю | скасовується, запис не змінюється | запис не змінюється |

Після скасування бот пише «Скасовано» і прибирає кнопки з повідомлення, що чекало відповіді. Витрата, записана як «нерозпізнане», отримує звичайне підтвердження «⚠️ Записано як нерозпізнане» з кнопкою \[✏️ Змінити\].

### **3.13. Збій запису в Google-таблицю** {#3.13.-збій-запису-в-google-таблицю}

1. Якщо таблиця недоступна або запис не вдався, бот зберігає дані та відповідає одним повідомленням:

> ⚠️ Не вдалося записати в таблицю: 45 · здоровʼя · аптека \[🔄 Повторити\] \[❌ Скасувати\]

2. «Повторити» робить нову спробу з тими самими даними. Так само бот поводиться, якщо збій стався під час зміни, коментаря чи видалення.

### **3.14. Інтеграції** {#3.14.-інтеграції}

* **Google Sheets** — єдина інтеграція: кожна витрата одразу записується в особисту таблицю власника.  
* ШІ, банківські API та курси валют не входять у першу версію.

## **5\. Архітектура та логіка роботи (User Flow)** {#5.-архітектура-та-логіка-роботи-(user-flow)}

### **5.1. Структура коду** {#5.1.-структура-коду}

Пропозиція для розробника (можна змінювати): логіка розділена на незалежні частини, щоб їх можна було перевіряти окремо.

| Файл | Що робить |
| ----- | ----- |
| `app/main.py` | запуск бота, підключення обробників, список команд меню |
| `app/config.py` | читання `.env` |
| `app/handlers/` | обробка повідомлень, команд і натискань кнопок |
| `app/parser.py` | виділення суми, опису й дати з тексту |
| `app/categorizer.py` | нормалізація, пошук у словнику, нечіткий пошук, самонавчання |
| `app/sheets.py` | уся робота зі сховищем: спершу тимчасовий JSON-файл, потім Google-таблиця (див. 10.1); інші файли від цієї заміни не змінюються |
| `app/keyboards.py` | inline-кнопки |
| `app/texts.py` | усі тексти бота в одному місці |

Тимчасовий стан (що бот зараз чекає, дані для «Відновити» і «Повторити») зберігається в пам'яті бота (FSM aiogram). Після перезапуску він зникає — це прийнятно для першої версії.

### **5.2. Основні сценарії** {#5.2.-основні-сценарії}

**А. Швидкий запис (слово відоме)**

1. Користувач: «150 biedronka».  
2. Бот розпізнає суму 150, опис «biedronka», категорію «їжа».  
3. Записує рядок у таблицю, прибирає кнопки з попереднього підтвердження.  
4. Надсилає «✅ Додано: 150 · їжа · biedronka» з кнопками дій.

**Б. Невідоме слово**

1. Користувач: «200 Decathlon».  
2. Бот: «Не впізнав категорію. Оберіть:» \+ кнопки категорій.  
3. Користувач обирає «одяг» → запис, підтвердження, слово стає кандидатом (при другому такому виборі — активним).

**В. Сумнівне розпізнавання**

1. Користувач: «200 rossman».  
2. Бот: «200 — «rossman» → побут?» \[✅ Так\] \[Інша категорія\] \[❌ Скасувати\].  
3. «Так» → запис. «Інша категорія» → список категорій з \[⬅️ Назад\], далі як у сценарії Б (з перевіркою конфлікту).

**Г. Запис через меню**

1. «Меню» → `/add` → список категорій.  
2. Вибір категорії → «Введіть суму» \[⬅️ Назад\] \[❌ Скасувати\].  
3. Сума (з описом або без) → запис і підтвердження.

**Ґ. Дії з записом**: зміна (3.8), коментар (3.9), видалення й відновлення (3.10), старі записи через `/last` (3.11).

### **5.3. Блок-схема** {#5.3.-блок-схема}

Блок-схема ведеться в [Miro](https://miro.com/app/board/uXjVEVUkCjE=/): схема буде доопрацьована й узгоджена з цим ТЗ окремо. У разі розбіжностей діє текст ТЗ.

### **5.4. Команди** {#5.4.-команди}

Назви команд — латиницею (вимога Telegram), описи в меню — українською.

| Команда | Опис у меню | Дія |
| ----- | ----- | ----- |
| `/start` | — (не показується в меню) | привітання й приклад введення |
| `/add` | Додати витрату (вибрати категорію) | сценарій Г |
| `/last` | Останні 5 записів | п. 3.11 |

## **6\. Інтерфейс (UI/UX)** {#6.-інтерфейс-(ui/ux)}

### **6.1. Типи кнопок** {#6.1.-типи-кнопок}

| Вид | Використання |
| ----- | ----- |
| Inline-кнопки під повідомленнями | вибір категорії, підтвердження, дії з записом, «Назад», «Скасувати» |
| Кнопка «Меню» Telegram | список команд з п. 5.4 |
| Постійна клавіатура (Reply keyboard) | не використовується: займає пів екрана й заважає швидкому введенню |

### **6.2. Правила навігації** {#6.2.-правила-навігації}

1. \[❌ Скасувати\] є в кожному кроці, де бот чекає відповіді.  
2. \[⬅️ Назад\] є лише у вкладених меню (вибір категорії після `/add`, «Інша категорія», «Що змінити?», запис у `/last`). Глибина — не більше 3 рівнів.  
3. Під час переходу між рівнями бот редагує те саме повідомлення, а не надсилає нове.  
4. Користувач ніколи не «застрягає»: діють правила п. 3.12 і команда `/cancel`.  
5. Натискання старої кнопки, дія якої вже неактуальна, нічого не змінює: бот показує коротке спливаюче повідомлення «Ця дія вже недоступна».

### **6.3. Тексти бота** {#6.3.-тексти-бота}

* Мова інтерфейсу — українська.  
* Тон — короткий і дружній, звернення на «ви». Одне повідомлення — не більше 3–4 рядків тексту.  
* Формат запису в повідомленнях: `сума · категорія · опис [· дата]`.  
* Емодзі лише як маркери: ✅ записано, 💰 нова витрата, 🧠 словник, 💬 коментар, 🗑 видалено, ⚠️ помилка або «нерозпізнане».  
* Усі тексти зібрані в одному файлі (`app/texts.py`), щоб їх легко було змінювати.  
* Бот надсилає лише текст; медіафайлів у першій версії немає.  
* Аватар і опис бота в @BotFather: особистий Telegram-бот для швидкого обліку витрат.

## **7\. Керування налаштуваннями та даними** {#7.-керування-налаштуваннями-та-даними}

Окремої панелі адміністратора немає: її роль виконує сама Google-таблиця. Користувачів, ролей і розсилок у боті немає.

| Що зробити | Де |
| ----- | ----- |
| Виправити або видалити витрату | у боті (кнопки, `/last`) або вручну у вкладці «Витрати» |
| Дорозподілити «нерозпізнане» | фільтр за категорією в «Витратах» або \[✏️ Змінити\] у боті |
| Додати, виправити або видалити ключове слово | вкладка «Словник» |
| Змінити список або порядок категорій, пороги, тайм-аут | вкладка «Налаштування» |
| Змінити токен, таблицю або власника | файл `.env`, потім перезапуск бота |

Якщо категорію перейменовано в налаштуваннях, старі записи та словник автоматично не оновлюються — їх виправляють у таблиці вручну.

## **8\. Нефункціональні вимоги** {#8.-нефункціональні-вимоги}

### **8.1. Безпека та конфіденційність** {#8.1.-безпека-та-конфіденційність}

1. Токен бота, ID таблиці, Telegram ID власника та часовий пояс зберігаються лише в `.env`. У коді та в `.env.example` реальних значень немає.  
2. JSON-ключ сервісного акаунта Google лежить окремим файлом, шлях до нього — у `.env`.  
3. `.env` і файл ключа додані в `.gitignore` і ніколи не потрапляють на GitHub. Перед кожним merge перевіряти, що секрети не потрапили в коміт.  
4. Бот відповідає лише власнику (п. 3.1).  
5. Таблиця відкрита тільки власнику й сервісному акаунту бота («Редактор»); доступ «за посиланням» вимкнено.  
6. У логи бота не записуються токени та ключі.

### **8.2. Продуктивність** {#8.2.-продуктивність}

1. Відповідь на витрату — до 3 секунд вразі доступності Google Sheets.  
2. Навантаження — один користувач, до кількох десятків записів на день; обмеження Google API це дозволяють.  
3. Словник допускається кешувати в пам'яті на короткий час (до 1 хв), щоб не читати таблицю на кожне повідомлення.

### **8.3. Хостинг і стабільність** {#8.3.-хостинг-і-стабільність}

1. На час розробки й тестування бот запускається на Mac власниці (режим polling) і працює, поки відкрито термінал. Повідомлення, надіслані, коли бот був вимкнений, Telegram зберігає до 24 годин, і бот обробляє їх після запуску. Тому під час запуску накопичені повідомлення не скидаються (заборонено `drop_pending_updates=True`).  
2. Постійний хостинг 24/7 та бюджет на нього: ❓ **уточнити** (вирішується на етапі 3).  
3. Після збою чи перезапуску бот продовжує роботу без втрати вже записаних даних (все в таблиці). Втрачається лише тимчасовий стан (незавершені дії).  
4. Помилки пишуться в лог (термінал або файл), щоб їх можна було показати Claude під час налагодження.

### **8.4. Розгортання копій** {#8.4.-розгортання-копій}

1. Налаштування копії винесені з коду: нова копія \= новий `.env` \+ копія шаблону таблиці, код не змінюється.  
2. Можливий запуск кількох копій на одному сервері з різними файлами налаштувань.  
3. До комплекту входять: код, `requirements.txt`, `.env.example`, шаблон Google-таблиці, `README.md` з інструкцією запуску.  
4. Інструкція для нового користувача (створення бота в @BotFather, копія таблиці, доступ сервісному акаунту) пишеться після тестування.

## **9\. Поза межами першої версії** {#9.-поза-межами-першої-версії}

Ці функції відкладено. Архітектура першої версії не має заважати їх додати.

1. **Аналітика та звіти**: текстові зведення й кругові діаграми за день, тиждень, місяць або довільний період. Попереднє рішення: звіти в Telegram рахує й малює сам бот, у таблиці — опційний «Дашборд» для перегляду на комп'ютері.  
2. **Доходи**.  
3. **Розпізнавання за допомогою ШІ** (Claude або OpenAI API) як запасний рівень після словника.  
4. **Кілька валют** з автоматичною конвертацією.  
5. **Бюджет і ліміти**: місячний ліміт на категорію з попередженням, загальний бюджет на місяць.  
6. **Екран налаштувань у боті**: мова, базова валюта, власні категорії, сповіщення.  
7. **Кілька користувачів** в одному боті та спільний бюджет.  
8. **Кілька витрат в одному повідомленні** («150 продукти, 40 таксі»).  
9. **Дата текстом у повідомленні** («25.10 300 оренда»); зараз — лише через \[✏️ Змінити\].  
10. **Інтеграція з банками** для автоматичного імпорту витрат.  
11. **Підготовка до продажу**: інструкція для покупця, ліцензія, матеріали про обробку даних (RODO).  
12. **Відповідь Reply** як спосіб додати коментар — відхилено, переглянути за потреби.

### **10.1. Порядок робіт у Етапі 1** {#10.1.-порядок-робіт-у-етапі-1}

Інтерфейс робиться спершу з тимчасовим сховищем, але підключення до Google перевіряється в перший же день: це найризикованіша частина робіт.

1. **Старт проєкту**: репозиторій `financebot`, віртуальне середовище Python, `requirements.txt`, `.env` \+ `.env.example`, `.gitignore`; бот відповідає на `/start` лише власниці.  
2. **Перевірка Google**: сервісний акаунт, ключ, доступ до шаблону таблиці; окремий маленький скрипт додає один рядок у вкладку «Витрати». До завершення цього кроку далі не йдемо.  
3. **Інтерфейс з тимчасовим сховищем**: розпізнавання суми, опису й дати, словник, кнопки категорій, `/add`, підтвердження. Дані тимчасово зберігаються в JSON-файл, але через `app/sheets.py` з тими самими діями, що й для таблиці: додати запис, знайти за ID, змінити, видалити, прочитати словник і налаштування.  
4. **Інтеграція**: JSON-сховище замінюється на Google-таблицю всередині `app/sheets.py`; решта коду не змінюється. Після цього — перевірка за критеріями 10.2.

Готове середовище з курсу (Homebrew, git, вхід у GitHub через `gh`, Cursor/VS Code з Claude Code, Python) використовується як є. Docker і ngrok для цього бота не потрібні.

### **10.2. Критерії приймання Етапу 1** {#10.2.-критерії-приймання-етапу-1}

- [ ] `/start` від власника — привітання; з іншого акаунта бот мовчить  
- [ ] «150 продукти» і «продукти 150» дають однаковий рядок у таблиці з категорією «їжа»  
- [ ] «12,27 таксі» і «12.27 таксі» записуються як число 12,27  
- [ ] «білет автобус Варшава 5» → категорія «проїзд», опис збережено повністю  
- [ ] «вчора 300 чинш» і «wczoraj 300 czynsz» записуються вчорашньою датою  
- [ ] «200 Decathlon» → кнопки категорій; після вибору — рядок у таблиці; «Скасувати» — нічого не записано  
- [ ] «150» без опису → кнопки категорій; «продукти» без числа → «Яка сума?»  
- [ ] `/add` → категорія → сума створює запис; «Назад» повертає до списку категорій  
- [ ] Слово, додане вручну у вкладку «Словник», розпізнається без перезапуску бота  
- [ ] У репозиторії на GitHub немає `.env` і ключа Google

### **10.3. Критерії приймання Етапів 2–3** {#10.3.-критерії-приймання-етапів-2–3}
